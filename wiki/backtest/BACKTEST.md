# Backtest

This document defines the reusable backtest mechanism used for screener signals.

It does not contain result analysis. Current result interpretation belongs in `BACKTEST_ANALYSIS.md`.

## Script

```text
scripts/backtest.py
```

Run for the swing screener:

```bash
bash backtest.sh --swing
```

Run for the MACD screener:

```bash
bash backtest.sh --macd
```

Run all screeners:

```bash
bash backtest.sh --all
```

Run with a different holding period:

```bash
bash backtest.sh --swing --hold-days 3
```

The shell script calls `scripts/backtest.py`. You can also run the Python implementation directly.

Direct run for the swing screener:

```bash
./venv/bin/python scripts/backtest.py \
  --input-pattern "ihsg_swing_indicators_*.csv" \
  --signal-column swing_candidate \
  --strategy-name swing
```

Direct run for the MACD screener:

```bash
./venv/bin/python scripts/backtest.py \
  --input-pattern "ihsg_macd_indicators_*.csv" \
  --signal-column macd_candidate \
  --strategy-name macd
```

## Input

The backtest reads a processed indicator dataset:

```text
data/processed/ihsg_<strategy>_indicators_<latest-date>.csv
```

Required columns:

```text
date
symbol
open
high
low
close
score
<signal-column>
return_5d
return_20d
volume_ratio
avg_value_20d
```

## Signal

The backtest uses rows where the configured signal column is true.

```text
<signal-column> = True
```

For example:

```text
swing_candidate = True
macd_candidate = True
```

The signal itself is generated by the relevant indicator builder.

## Entry Rule

For a signal on date `T`:

```text
entry_date = next available trading day for the same symbol
entry_price = entry_date open
```

Reason:

The screener is only known after the signal day closes, so entering on the same close would be optimistic. Next-day open is a cleaner assumption.

## Exit Rule

Default:

```text
hold_days = 5
exit_date = 5 trading days after signal date
exit_price = exit_date close
```

This matches the repo objective of testing roughly one-week swing trades.

## Overlap Rule

Default:

```text
overlapping trades for the same symbol = disabled
```

If a symbol already has an active trade, new signals for that symbol are ignored until the current trade exits.

To allow overlapping trades:

```bash
bash backtest.sh --swing --allow-overlap
```

## Trade Metrics

For every trade:

```text
return = exit_price / entry_price - 1
return_pct = return * 100
max_gain_pct = highest high during holding window / entry_price - 1
max_loss_pct = lowest low during holding window / entry_price - 1
win = return > 0
```

The trade row also stores signal context:

```text
signal_score
signal_return_5d
signal_return_20d
signal_volume_ratio
signal_avg_value_20d
```

## Output Reports

Trade-level report:

```text
data/reports/<strategy>/backtest_trades_<strategy>_<latest-date>_<hold-days>d.csv
```

Overall summary:

```text
data/reports/<strategy>/backtest_summary_<strategy>_<latest-date>_<hold-days>d.csv
```

By-symbol summary:

```text
data/reports/<strategy>/backtest_by_symbol_<strategy>_<latest-date>_<hold-days>d.csv
```

By-score summary:

```text
data/reports/<strategy>/backtest_by_score_<strategy>_<latest-date>_<hold-days>d.csv
```

## Summary Metrics

```text
trades
win_rate
average_return
median_return
best_trade
worst_trade
profit_factor
sequential_max_drawdown
```

`sequential_max_drawdown` is calculated from the sequence of trade returns in the report. It is not a full portfolio-level drawdown because this backtest does not yet model capital allocation, simultaneous positions, or position sizing.

## Current Limitations

The current backtest does not include:

```text
transaction costs
slippage
bid/ask spread
position sizing
portfolio cash constraints
stop loss
take profit
market regime filter
```

Because of that, it should be treated as a signal-quality test, not a complete trading system simulation.
